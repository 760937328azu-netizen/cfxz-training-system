1. 部署概览与架构

本系统采用统一部署模式：前端静态文件和后端 API 运行在同一个 Node.js 服务中。

✦

架构说明：

• 用户访问 HTTPS 域名 → 平台负载均衡 → Node.js Express 服务（端口 4000）

• Express 服务同时处理：/api/* API 请求 + /* 前端静态文件

• 数据库连接：Supabase PostgreSQL（Session Pooler，端口 5432）

• 前端通过相对路径 /api 访问后端，无需 CORS 跨域配置

✅ 生产构建已在本地验证通过：健康检查、前端 HTML 托管、SPA 路由回退均正常。

5. 方案 A：Railway 部署（推荐）

Railway 是最简单的部署方案，自动构建、自动 HTTPS、自动健康检查。

1

注册 Railway 账号

访问 https://railway.app → 使用 GitHub 账号登录

2

创建新项目

点击 "New Project" → "Deploy from GitHub repo" → 选择你的 cfxz-training 仓库

3

配置构建

Railway 会自动检测 Dockerfile 并使用它构建。无需额外配置。

构建过程中会自动执行：前端构建 → 后端构建 → 生成 Prisma Client → 打包生产镜像

4

设置环境变量

在 Railway 项目的 "Variables" 标签页中，逐项添加以下变量：

变量名值说明
DATABASE_URLpostgresql://postgres.[ref]:[pwd]@aws-0-[region].pooler.supabase.com:5432/postgres?connection_limit=5&pool_timeout=30&schema=trainingSupabase Session Pooler
DIRECT_URLpostgresql://postgres.[ref]:[pwd]@aws-0-[region].supabase.com:5432/postgres?schema=trainingSupabase 直连（迁移用）
JWT_SECRET64 字符随机字符串JWT 签名密钥
CORS_ORIGINShttps://你的应用名.up.railway.appRailway 分配的域名
SEED_ADMIN_NAME超级管理员管理员名称
SEED_ADMIN_USERNAMEadmin管理员账号
SEED_ADMIN_PASSWORDCfxz!Prod#2026Secure管理员密码
NODE_ENVproduction生产环境标记
PORT4000服务端口
注意 CORS_ORIGINS：先部署一次获取 Railway 分配的域名，再回来设置此变量。或者直接留空（允许所有来源）后部署。
5

配置健康检查

在 "Settings" → "Healthcheck" 中设置路径为 /api/health

Railway 会定期检查此路径，确保服务正常运行

6

生成域名

在 "Settings" → "Networking" → "Generate Domain"

Railway 会分配一个 HTTPS 域名，如：https://cfxz-training.up.railway.app

7

验证部署

访问 https://你的域名/api/health，应返回：

{"status":"ok","timestamp":"2026-07-25T..."}

访问 https://你的域名/，应看到培训系统登录页面

7. 方案 C：VPS 服务器部署

使用阿里云/腾讯云 ECS 服务器，完全可控，适合长期生产环境。

1

服务器准备

• 操作系统：Ubuntu 22.04 LTS

• 最低配置：2 核 CPU / 4GB 内存 / 40GB 磁盘

• 安装 Node.js 22、PM2、Nginx

curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - sudo apt-get install -y nodejs sudo npm install -g pm2 sudo apt-get install -y nginx
2

部署代码

cd /opt git clone https://github.com/你的用户名/cfxz-training.git cd cfxz-training npm ci npm run build cd server && npm ci && npx prisma generate && npm run build cp -r ../dist ./public
3

配置环境变量

cd /opt/cfxz-training/server cp .env.example .env nano .env # 填入生产环境变量
4

使用 PM2 启动服务

cd /opt/cfxz-training/server NODE_ENV=production pm2 start dist/index.js --name cfxz-training pm2 save pm2 startup # 设置开机自启
5

配置 Nginx 反向代理 + SSL

server { listen 80; server_name your-domain.com; location / { proxy_pass http://127.0.0.1:4000; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }

使用 Certbot 配置免费 SSL 证书：

sudo apt-get install certbot python3-certbot-nginx sudo certbot --nginx -d your-domain.com

8. 环境变量配置清单

无论选择哪个平台，都需要配置以下环境变量：

变量名是否必填说明
DATABASE_URL必填Supabase Session Pooler 连接串（端口 5432），运行时使用
DIRECT_URL必填Supabase 直连串（端口 5432），Prisma 迁移使用
JWT_SECRET必填JWT 签名密钥（64 字符随机字符串）
CORS_ORIGINS必填允许的前端来源域名（部署平台的 HTTPS 域名）
SEED_ADMIN_NAME选填管理员名称（默认：超级管理员）
SEED_ADMIN_USERNAME选填管理员账号（默认：admin）
SEED_ADMIN_PASSWORD必填管理员密码（禁止使用 ChangeMe!2026）
NODE_ENV固定production
PORT固定4000
MOKA_WEBHOOK_SECRET后续Moka Webhook 签名密钥（对接 Moka 时填写）
重要：JWT_SECRET 可以从本地 server/.env 文件中复制，保持与本地开发环境一致可确保现有 JWT token 在生产环境仍然有效。

11. 常见问题排查

Q: 部署后访问页面白屏

检查浏览器控制台是否有 404 错误。确认 Dockerfile 构建阶段的前端产物已正确复制到 server/public 目录。

Q: API 请求返回 502 或超时

检查环境变量 DATABASE_URL 是否正确。确认 Supabase 项目状态为 Active。检查 Railway/Render 日志中是否有数据库连接错误。

Q: 登录返回 401

确认 JWT_SECRET 与本地开发环境一致。如果不一致，所有已签发的 token 将失效，需要重新登录。

Q: CORS 错误

将 CORS_ORIGINS 设置为部署平台分配的 HTTPS 域名。统一部署模式下前端和后端同域，通常不会出现 CORS 问题。

Q: Prisma 迁移错误

确认 DIRECT_URL 使用的是 Supabase 直连地址（非 Pooler）。Prisma 迁移需要直连，不能通过连接池。

Q: 构建过程中 npm install 超时

Railway/Render 的构建服务器在海外，如果拉取 npm 包超时，可以在 server/package.json 中添加中国镜像。但通常平台构建服务器网络良好，不需要镜像。
