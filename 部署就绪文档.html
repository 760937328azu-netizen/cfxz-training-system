长发小寨新员工培训系统 — 部署就绪文档

生成时间：2026-07-25 | 版本：v1.0 | 数据库：Supabase PostgreSQL | 后端：Node.js + Express + Prisma

前端 API 模式审计结论：当前前端已完全切换 API 模式。所有员工数据、学习进度、认证成绩、管理员权限均通过 API 从数据库读取。localStorage 仅用于 JWT token 存储、用户信息缓存和滚动位置恢复，不作为正式数据源。当 VITE_API_BASE_URL 未配置时降级到 localStorage 模式（仅用于开发/演示）。

三、登录流程

员工登录流程

  1. 前端输入：员工在 LoginPage 输入手机号 + 密码
  2. API 调用：POST /api/auth/employee/login，body: { phone, password }
  3. 后端验证：
    • 通过 phone 查找 users 表，确认 status === active
    • bcrypt.compare(password, password_hash) 验证密码
    • 验证通过 → 生成 JWT token（7天有效期），更新 last_login_at
    • 记录 login 事件到 learning_events 表
  4. 前端存储：
    • cfxz-auth-token → JWT token
    • 用户信息缓存（name/phone/department/employeeNo 等）
  5. 进度同步：useProgressSync() 自动调用 GET /api/progress 拉取完整进度到 localStorage 缓存
  6. 路由跳转：跳转到首页，展示成长地图

管理员登录流程

  1. 前端输入：管理员在 AdminLoginPage 输入用户名 + 密码
  2. API 调用：POST /api/auth/admin/login，body: { username, password }
  3. 后端验证：
    • 通过 username 查找 admin_users 表，确认 status === active
    • bcrypt.compare(password, password_hash) 验证密码
    • 验证通过 → 生成 JWT token（7天有效期），更新 last_login_at
  4. 前端存储：
    • cfxz-admin-auth-token → 管理员 JWT token
    • 管理员信息缓存（name/username/role）
  5. 数据同步：refreshAdminCache() 拉取员工列表、批次列表、管理员列表
  6. 路由跳转：跳转到管理后台 Dashboard

四、员工学习数据流

阶段 1：页面挂载 — 自动同步

当员工进入任意页面时，useProgressSync() Hook 自动触发：

  1. 调用 GET /api/progress（携带 JWT token）
  2. 后端从 4 张表联查：learning_progress + stage_progress + game_progress + certification_attempts
  3. 返回完整的 ProgressResponse（当前关卡、各关状态、游戏进度、认证状态、完成率）
  4. 前端通过 apiProgressToLocal() 转换为前端 LearningProgress 格式
  5. 写入 localStorage 作为缓存（key: cfxz-phase3-learning-progress-v2-{username}）

阶段 2：学习操作 — 乐观更新 + API 同步

当员工完成关卡/展区/游戏时，采用乐观更新模式：

  1. 乐观更新：先 writeProgress() 写入 localStorage，UI 立即更新（无延迟）
  2. API 同步：fire-and-forget 调用 progressApi.updateStage() 或 progressApi.updateGame()
  3. 后端写入：
    • 关卡进度 → 写入 stage_progress 表（status: pending → in_progress → completed）
    • 展区完成 → 追加到 completed_exhibits 数组
    • 游戏进度 → 写入 game_progress 表，检测四关全通后自动标记 rules 关卡 completed
    • 学习事件 → 记录到 learning_events 表（stage_complete / game_complete）
  4. 错误处理：API 调用失败时静默忽略（localStorage 缓存仍正确），下次挂载时重新同步

阶段 3：认证考试 — 完整链路

  1. 拉取题目：GET /api/certification/questions → 从 question_bank 表获取当前激活版本题目（不暴露 correctIndex）
  2. 答题提交：POST /api/certification/submit → 后端评分
  3. 评分逻辑：score >= 80 → passed = true
  4. 数据库写入：
    • 保存考试记录到 certification_attempts 表
    • 如果通过 → 更新 learning_progress.learning_world_unlocked = true
    • 记录 cert_passed 事件到 learning_events
  5. 前端响应：显示考试结果 + 错题详情 + 解析 → 解锁"学习天地"模块

五、Moka 对接接口位置

Moka Webhook 入口：POST /api/moka/webhook

对接流程

  1. Moka 配置 Webhook URL：在 Moka 系统中配置 Webhook 地址指向后端 https://[your-domain]/api/moka/webhook
  2. 签名验证：后端通过 MOKA_WEBHOOK_SECRET 验证请求签名，防止伪造
  3. 事件处理：
    • employee_onboard → 创建新员工（自动初始化 progress + 6 个 stage + 4 个 game）
    • employee_update → 更新员工信息
    • employee_leave → 将员工 status 设为 disabled
  4. 同步记录：所有 webhook 数据保存到 moka_sync_events 表，支持后续审计和重放

需要配置的环境变量

变量用途状态
MOKA_API_BASE_URLMoka API 基础 URL当前留空
MOKA_API_KEYMoka API 密钥（仅服务端使用）当前留空
MOKA_RSA_PRIVATE_KEYRSA 私钥（用于签名验证）当前留空
MOKA_WEBHOOK_SECRETWebhook 签名密钥当前留空

安全说明：所有 Moka 密钥仅存在服务端 .env 文件中，前端代码不包含任何 Moka 密钥。

六、上线前安全检查清单

以下 5 项必须在上线前逐项确认完成：
#检查项当前状态操作说明
1 测试账号删除 待执行 数据库建表后，删除 seed 产生的测试员工（如有）。确保生产环境无测试数据残留
2 admin 默认密码修改 待执行 在 server/.env 中将 SEED_ADMIN_PASSWORD 从 ChangeMe!2026 改为强密码（至少 12 位，含大小写+数字+符号）

额外安全建议

  • CORS_ORIGINS：生产环境仅配置实际域名，移除 localhost
  • HTTPS：确保后端和前端均通过 HTTPS 提供服务
  • Supabase 连接池：使用 Supabase 的连接池模式（端口 6543），避免连接数耗尽
  • 数据库备份：在 Supabase Dashboard 开启自动备份
  • 密码策略：员工初始密码由 generateInitialPassword() 生成 8 位随机密码，首次登录后建议修改
  • 速率限制：建议后续在登录接口添加速率限制（当前未实现）

七、部署执行步骤

Step 1：配置 Supabase 数据库

  1. 登录 Supabase Dashboard，创建新项目
  2. 进入 Settings → Database → Connection string → URI
  3. 复制连接字符串（格式：postgresql://postgres:[PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres）
  4. 将连接字符串填入 server/.env 的 DATABASE_URL

Step 2：配置后端环境变量

  1. 复制 server/.env.example 为 server/.env
  2. 修改以下必填项：
    • DATABASE_URL → Supabase 连接字符串
    • JWT_SECRET → 运行 openssl rand -base64 64 生成
    • SEED_ADMIN_PASSWORD → 改为强密码
    • CORS_ORIGINS → 改为实际前端域名

Step 3：建表 + 初始化种子数据

  1. cd server
  2. npx prisma db push → 创建 11 张表到 Supabase
  3. npx prisma generate → 生成 Prisma Client
  4. npx tsx src/seed.ts → 初始化超级管理员 + 20 道认证题库（v1.0）

Step 4：配置前端环境变量

  1. 在项目根目录创建 .env 文件
  2. 添加：VITE_API_BASE_URL=https://[your-backend-domain]:4000
  3. 确保 isApiMode() 返回 true

Step 5：启动服务 + 联调验证

  1. 启动后端：cd server && npm run dev（端口 4000）
  2. 启动前端：npm run dev（端口 5173）
  3. 访问 http://localhost:5173 测试员工登录
  4. 访问 http://localhost:5173/#/admin 测试管理员登录
  5. 创建测试员工 → 员工登录 → 完成关卡 → 认证考试 → 验证数据同步

Step 6：创建测试员工（用于联调）

管理员登录后台后，在员工管理页面创建测试员工：

  • 姓名：测试员工
  • 手机号：13800000001
  • 系统自动生成初始密码
  • 使用该账号登录前端，验证完整学习流程

上线前删除测试员工。
